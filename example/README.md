# Example fixtures

Each fixture is a minimal app that renders the shared screen in [`shared/NavigationModeScreen.js`](shared/NavigationModeScreen.js). The screen shows every public API, the detection source, errors, and the running architecture, and logs the same data to logcat with the prefix `[NavigationModeExample]`.

| Fixture | React Native | Architectures |
| --- | --- | --- |
| `rn-0.71` | 0.71.19 | Legacy |
| `rn-0.76` | 0.76.9 | Legacy and New (`-PnewArchEnabled=false/true`) |
| `rn-0.81` | 0.81.6 | Legacy and New |
| `rn-0.82` | 0.82.1 | New only (React Native ignores `newArchEnabled=false`) |
| `rn-0.88` | 0.88.1 | New only; `-PdisableTurboModuleInterop=true` turns off the TurboModule interop layer |
| `expo-sdk-58` | Expo SDK 58 (React Native 0.88.1) | New; Android project generated by `expo prebuild` |

The fixtures were created with the React Native / Expo CLI of their version and trimmed to Android. Their lockfiles pin exact dependency versions.

## Install the library into fixtures

Fixtures consume the library as a packed tarball, the same way consumers do:

```bash
example/scripts/install-library-into-fixtures.sh            # every fixture
example/scripts/install-library-into-fixtures.sh example/rn-0.88
```

The script runs `npm pack` at the repository root, then installs the tarball and `example/shared` into each fixture with `--install-links` (copies instead of symlinks, which older Metro versions cannot follow). Run it again after changing the library or the shared screen.

## Build

Each fixture needs JDK 17 (the library compiles with Java/Kotlin target 17, including on React Native 0.71) and the Android SDK.

```bash
cd example/rn-0.81/android
./gradlew -PnewArchEnabled=false assembleRelease   # Legacy Architecture
./gradlew -PnewArchEnabled=true assembleRelease    # New Architecture
```

Release builds bundle the JS, so they run without Metro. They are signed with the template's debug keystore.

For Expo, generate the native project first:

```bash
cd example/expo-sdk-58
npx expo prebuild --platform android
cd android && ./gradlew assembleRelease
```

## Kotlin unit tests

The tarball does not include `android/src/test`. Build the library from the repository sources instead:

```bash
cd example/rn-0.88/android
./gradlew -PuseLibrarySource=true :react-native-android-navigation-mode:testDebugUnitTest
```

## Check a device or emulator

1. Install a release APK: `adb install -r app/build/outputs/apk/release/app-release.apk`.
2. Open the app and read the result: `adb logcat -s ReactNativeJS | grep NavigationModeExample`.
3. Change the navigation style in Settings › System › Gestures › System navigation (on an emulator, `adb shell cmd overlay enable-exclusive --category com.android.internal.systemui.navbar.gestural` or `.threebutton`), return to the app, and read the log again.

### Window insets checks (`rn-0.88`)

The `rn-0.88` activity accepts fixture-only extras:

```bash
# App-owned insets listener: logs what the host app receives (tag NavigationModeExample)
adb shell am start -n com.navmodern088/.MainActivity --ez hostInsetsListener true
# Hide / show the navigation bar
adb shell am start -n com.navmodern088/.MainActivity --ez immersive true
adb shell am start -n com.navmodern088/.MainActivity --ez immersive false
# Render a text input; tap it to open the keyboard
adb shell am start -a android.intent.action.VIEW -n com.navmodern088/.MainActivity -d "navmode-example://keyboard"
```

Read the library result with `adb logcat -s ReactNativeJS | grep NavigationModeExample` and the host listener with `adb logcat -s NavigationModeExample`. On an AVD with `hw.keyboard=yes`, enable `adb shell settings put secure show_ime_with_hard_keyboard 1` so the soft keyboard appears.

Emulators only cover AOSP behavior. OEM navigation implementations need real devices.
