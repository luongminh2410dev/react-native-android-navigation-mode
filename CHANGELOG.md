# Changelog

## 1.1.0 — 2026-10-29

### Added

- `getAndroidNavigationModeInfo()` and `useAndroidNavigationModeInfo()`: detailed result with `mode` (including `'unknown'`), `interactionMode` and `source`.
- Android 9 detection of the swipe-up 2-button mode via `swipe_up_to_switch_apps_enabled`.
- `getAndroidNavigationBarInsets()`, `getAndroidNavigationBarHeight()` and `useAndroidNavigationBarInsets()`: visible navigation bar insets of the current window, in dp.
- New Architecture support as a TurboModule generated by Codegen (`codegenConfig` in `package.json`). The Legacy Architecture keeps working through the same native module name.

### Fixed

- A system resource value outside `0/1/2`, or a failed resource read, now falls back to the `navigation_mode` secure setting instead of reporting `3-button` or throwing. This can change the value returned by `getAndroidNavigationMode()` on affected devices.
- Android 9 devices using the swipe-up gesture now report `2-button` from `getAndroidNavigationMode()` instead of `3-button`.
- Android builds on hosts whose root project does not provide the Kotlin Gradle plugin (for example React Native 0.71 app templates).

### Changed

- The native module is resolved through `TurboModuleRegistry` when a getter runs on Android, instead of through `NativeModules` at import time.

### Upgrade notes

- Rebuild the Android app after upgrading: the new JS API needs the new native methods. Calling a new getter against an old binary throws (or rejects) with an error asking for a rebuild.
